Модуль 1 — Основы OWASP ZAP

От установки до первых находок: перехват трафика, SQL-инъекции, XSS и CSRF на легальных полигонах.

Прогресс модуля 0%

Введение

ZAP — перехватывающий прокси, который даёт полный контроль над HTTP-трафиком между браузером и сервером. Вы видите каждый запрос, можете изменить его на лету и понять, как именно работают уязвимости — на практике, а не в теории.

Что освоите: настройку ZAP как локального прокси, ручной перехват, автоматическое сканирование, поиск SQLi/XSS/CSRF на учебных полигонах.

📌 Факт

Первый релиз ZAP вышел в сентябре 2010 года. В 2015 и 2016 годах читатели ToolsWatch признавали его «Top Security Tool».

Установка

ZAP — Java-приложение. Современные версии требуют Java 17+.

Windows

winget install --id=ZAP.ZAP -e

macOS

brew install --cask zap
При первом запуске ZAP предложит сохранить сессию — для обучения выберите «No».

Настройка прокси

По умолчанию ZAP слушает localhost:8080 (Tools → Options → Network → Local Servers/Proxies).

1
Настройте браузер. Firefox: Настройки → Network Settings → Manual proxy. HTTP Proxy 127.0.0.1, порт 8080. Галочка «Use for all protocols».
2
Доверьте сертификат. Tools → Options → Network → Server Certificates — сохраните и импортируйте в браузер. Без этого HTTPS не откроется.
3
Проверьте. Откройте сайт — записи должны появиться на вкладке «History».

Перехват запросов

Кнопка «Intercept» (Ctrl+B) останавливает запросы до отправки. Меняйте параметры, заголовки, метод.

Никогда не перехватывайте и не модифицируйте запросы к чужим системам без письменного разрешения.

Пример: SQLi через перехват

В поле логина вместо admin введите ' OR '1'='1. Отправьте запрос. Если сервер пустил без пароля — вы нашли SQL-инъекцию (в учебных целях).

Автоматическое сканирование

🕷️ Spider

Обход ссылок. Правый клик по URL → Attack → Spider…. Укажите пользователя, если сайт за логином.

⚡ Active Scan

Attack → Active Scan… — отправляет payload'ы для поиска SQLi, XSS, path traversal. Результаты — на вкладке «Alerts».

Три классические уязвимости

Высокий риск

SQL-инъекция

Ввод пользователя попадает в SQL-запрос без разделения кода и данных. Пример: ' OR '1'='1 обходит аутентификацию.

Защита: параметризованные запросы (prepared statements).

История: в 2007–2009 гг. Альберт Гонсалес использовал SQLi для кражи 130+ млн карт. Приговор — 20 лет тюрьмы, Heartland выплатила ~140 млн долларов.

Средний/высокий риск

XSS

Ввод возвращается в HTML без экранирования. Пример: <script>alert('XSS')</script>.

Защита: HTML-encoding, CSP, валидация.

История: червь Samy на MySpace (2005) заразил 1 млн профилей за сутки. Автор оштрафован на $15 000.

Средний риск

CSRF

Браузер жертвы автоматически прикрепляет cookies. Скрытая форма на стороннем сайте выполняет действие от имени жертвы.

Защита: CSRF-токены, SameSite cookies, проверка Origin/Referer.

История: в 2007 году CSRF в Gmail позволил захватить домен жертвы.

Исторические кейсы

Статья Джеффа Форристала в Phrack под псевдонимом rain.forest.puppy положила начало публичному обсуждению SQL-инъекций.

Stored XSS-червь заразил миллион профилей за сутки. Автор — Сэми Камкар — оштрафован на $15 000.

Альберт Гонсалес и сообщники атаковали Heartland, 7-Eleven, Hannaford. Приговор — 20 лет тюрьмы.

Классическая SQL-инъекция привела к утечкам в тысячах организаций. Инъекции остаются актуальными.

Этика и закон

Только с разрешения. Тестирование чужих систем без письменного согласия — уголовное преступление.

Используйте только учебные полигоны (Juice Shop, DVWA, Testfire) или собственные системы.
