OWASP ZAP: Модуль 3 — Исследование безопасности сервера

Веб-приложение — это лишь вершина айсберга. Под ним — операционная система, сетевые сервисы, веб-сервер (Nginx, Apache), база данных и контейнеры. Уязвимость на любом из этих уровней может свести на нет всю защиту приложения. В этом модуле вы научитесь исследовать сервер целиком: от открытых портов до конфигурации ядра и образов Docker.

Что нового: Nmap для карты сети, Lynis для аудита ОС, OpenVAS для поиска CVE, Nuclei для шаблонных проверок, Trivy для контейнеров, DefectDojo для управления находками и OWASP WSTG как методологическая основа.
Этика: все описанные техники применяйте только к собственным серверам или системам, на которые у вас есть письменное разрешение. Несанкционированное сканирование является нарушением закона.

Nmap: карта сети и открытых портов

Nmap (Network Mapper) — фундамент любого аудита. Он показывает, какие хосты живы, какие порты открыты, какие сервисы и версии на них работают, и какая ОС установлена[reference:0].

🔍 SYN-сканирование (-sS)

По умолчанию, быстрое и относительно скрытное. Не завершает TCP-рукопожатие, поэтому менее заметно для логов. Требует root.

sudo nmap -sS 192.168.1.10

🔌 UDP-сканирование (-sU)

Находит сервисы на UDP: DNS (53), SNMP (161), NTP (123). Медленнее TCP, но без него карта неполная.

sudo nmap -sU --top-ports 200 192.168.1.10

⚡ Агрессивное сканирование (-A)

Один проход: определение ОС, версий сервисов, выполнение NSE-скриптов по умолчанию и трассировка. Максимум информации, но заметно.

sudo nmap -A 192.168.1.10

📋 Полное сканирование портов (-p-)

Проверяет все 65 535 портов, а не только топ-1000. Обязательно для тщательного аудита.

sudo nmap -sS -p- 192.168.1.10

Nmap Scripting Engine (NSE)

Более 600 скриптов для проверки уязвимостей, перечисления сервисов и аутентификации[reference:1]. Категории: auth, brute, vuln, safe, exploit и др.

# Проверка на EternalBlue (MS17-010)
nmap -p 445 --script smb-vuln-ms17-010 192.168.1.10

# Все SMB-уязвимости
nmap -p 445 --script "smb-vuln-*" 192.168.1.10
Совет: сохраняйте результаты в XML (-oX) — этот формат затем можно импортировать в OpenVAS или другие инструменты[reference:2].

Lynis: аудит конфигурации операционной системы

Lynis — это инструмент аудита безопасности для Linux, macOS и Unix-систем. Он проверяет конфигурацию ядра, права файлов, SSH, firewall, установленные пакеты и многое другое, а в конце выдаёт индекс защищённости (Hardening Index) от 0 до 100[reference:3].

1
Установите Lynis из репозитория CISOFY или пакетного менеджера вашего дистрибутива[reference:4].
2
Запустите аудит: sudo lynis audit system. Аудит только для чтения и не вносит изменений в систему — его безопасно запускать в любое время[reference:5].
3
Разберите вывод: [OK] — проверка пройдена; [WARNING] — потенциальная проблема; [SUGGESTION] — рекомендация по улучшению[reference:6].
4
Изучите отчёты: подробный лог — /var/log/lynis.log, сводка — /var/log/lynis-report.dat[reference:7].

Что проверяет Lynis

Инструменты и команды системы, загрузку и сервисы, конфигурацию ядра, целостность файловой системы, пользователей и аутентификацию, права файлов, SSH, сеть, firewall, пакеты ПО, логирование и аудит[reference:8].

OpenVAS (Greenbone): сканер уязвимостей с базой CVE

OpenVAS — это полноценный сканер уязвимостей с открытым исходным кодом, который проверяет серверы на наличие известных CVE, слабых конфигураций и отсутствующих патчей.

🐳 Развёртывание через Docker (рекомендуется)

Greenbone Community Edition проще всего запустить через Docker Compose[reference:9][reference:10]:

mkdir -p ~/greenbone-community-container
cd ~/greenbone-community-container
curl -f -O -L https://greenbone.github.io/docs/latest/_static/docker-compose.yml
docker compose pull
docker compose up -d

Веб-интерфейс доступен по HTTPS. Учётные данные по умолчанию: admin / admin[reference:11].

📋 Рабочий процесс в веб-интерфейсе (GSA)

1. Configuration → Credentials — опционально добавьте SSH/SMB-учётные данные для аутентифицированного сканирования (даёт более глубокий результат).

2. Configuration → Targets — создайте цель: хост или подсеть, список портов.

3. Configuration → Scan Configs — выберите политику сканирования (например, «Full and fast» или «Full and very deep»).

4. Запустите сканирование и дождитесь отчёта с CVE и оценками риска[reference:12].

Требования: для комфортной работы OpenVAS нужно минимум 2 CPU и 4 ГБ RAM (рекомендуется 4 CPU / 8 ГБ)[reference:13].

Nuclei: быстрые шаблонные проверки и CI/CD

Nuclei — современный высокопроизводительный сканер уязвимостей, основанный на простых YAML-шаблонах. Каждый шаблон описывает конкретную проверку (CVE, мисконфигурация, экспозиция сервиса) и может быть легко расширен[reference:14].

Установка и базовый запуск

# Установка (требуется Go 1.23+)
go install -v github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest

# Сканирование по всем шаблонам
nuclei -target https://example.com

# Только критичные и высокие
nuclei -target https://example.com -severity critical,high

Интеграция в CI/CD

Nuclei легко встраивается в пайплайны GitHub Actions, GitLab CI или Jenkins одной командой. Это позволяет проверять безопасность при каждом деплое[reference:15][reference:16].

nuclei -t ./nuclei-templates/ -target $TARGET_URL -severity critical,high
Сила Nuclei: сообщество поддерживает тысячи шаблонов, а вы можете писать собственные YAML-файлы под специфику вашего приложения или инфраструктуры.

Trivy: безопасность контейнеров Docker

Если вы используете Docker, уязвимость в базовом образе или зависимости может попасть в production вместе с вашим кодом. Trivy — самый популярный open-source сканер контейнеров: он находит CVE в пакетах ОС, зависимостях, а также секреты и мисконфигурации[reference:17].

Базовое сканирование образа

# Установка (macOS)
brew install aquasecurity/trivy/trivy

# Сканирование образа
trivy image nginx:1.25

Trivy автоматически загружает базу уязвимостей из NVD, GitHub Security Advisories и дистрибутивных фидов при первом запуске[reference:18].

Фильтрация и гейтинг сборки

# Только HIGH и CRITICAL
trivy image --severity HIGH,CRITICAL myapp:latest

# Падать со сборочным кодом 1, если есть CRITICAL
trivy image --exit-code 1 --severity CRITICAL myapp:latest

Это позволяет встроить проверку в CI/CD и не пропускать в registry образы с критическими уязвимостями[reference:19].

Сканирование файловой системы и IaC

Trivy также проверяет файловые системы на уязвимые зависимости и Terraform/Kubernetes-манифесты на мисконфигурации.

trivy fs --scanners vuln,secret .
trivy config ./terraform

DefectDojo: управление находками и жизненный цикл

После сканирования ZAP, OpenVAS, Nuclei и Trivy у вас на руках десятки отчётов. Без централизованной системы невозможно понять, что уже исправлено, что новое, а что принято как риск. DefectDojo — платформа управления уязвимостями, которая превращает разрозненные отчёты в единый список задач.

Интеграция с ZAP

DefectDojo импортирует XML-отчёты ZAP (baseline, full scan, API scan). Каждое оповещение ZAP становится Finding на соответствующем Asset, со всеми затронутыми URL как endpoints и сохранёнными запросами/ответами[reference:20].

# Генерация XML-отчёта ZAP
docker run -v $(pwd):/zap/wrk/:rw -t ghcr.io/zaproxy/zaproxy:stable \
  zap-baseline.py -t https://staging.example.com -x zap-report.xml

Что даёт DefectDojo

Дедупликация по заголовку, CWE и серьёзности — повторное сканирование не создаёт дубликатов.

Жизненный цикл: при повторном импорте находки, которые больше не воспроизводятся, автоматически закрываются, а вернувшиеся — реактивируются[reference:21].

SLA и владельцы: уровни риска ZAP маппятся на серьёзность DefectDojo, и каждая находка получает ответственного, дедлайн и тикет в Jira[reference:22].

Совет: DefectDojo поддерживает не только ZAP, но и OpenVAS, Nuclei, Trivy, Burp, Acunetix и многие другие форматы — это единая точка входа для всех сканеров.

OWASP WSTG: методология тестирования веб-сервера

OWASP Web Security Testing Guide (WSTG) — это флагманский проект OWASP, описывающий полный процесс тестирования безопасности веб-приложений и инфраструктуры. Раздел WSTG-CONF-01 (Network Infrastructure Configuration) напрямую посвящён веб-серверам.

Что проверять на уровне инфраструктуры (WSTG-CONF-01)

WSTG предписывает идентифицировать каждый элемент инфраструктуры (веб-сервер, сервер приложений, БД, балансировщик, CDN, контейнеры) и проверить его на:

  • Известные уязвимости серверного ПО.
  • Дефолтные учётные данные и настройки.
  • Административные интерфейсы (доступность извне).
  • Список разрешённых портов (контроль изменений).
  • Изоляцию сети для облачных и контейнерных сред[reference:23].

Чек-лист аудита веб-сервера

  • Проверить версию веб-сервера и отсутствие известных CVE (Nmap NSE, OpenVAS, Nuclei).
  • Убедиться, что дефолтные страницы, примеры и тестовые приложения удалены.
  • Проверить, что debug-режим и подробные сообщения об ошибках отключены.
  • Убедиться, что листинг директорий запрещён.
  • Проверить заголовки безопасности: CSP, HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy.
  • Проверить TLS: версии протокола, шифры, срок действия сертификата (SSL Labs, testssl.sh).
  • Убедиться, что административные панели (/admin, /manager) недоступны извне или защищены.
  • Проверить, что сервер работает с минимальными привилегиями (не root).
  • Проверить логирование и мониторинг: ошибки, попытки доступа к запрещённым путям.
  • Для контейнеров: просканировать образы Trivy и убедиться, что нет CRITICAL CVE в базовом образе.

Полный цикл аудита сервера: от разведки до отчёта

Соберём всё вместе в воспроизводимый процесс. Этот workflow можно адаптировать под размер инфраструктуры и уровень критичности.

1
Инвентаризация. Nmap: обнаружение хостов, открытых портов и сервисов. Сохраните результат в XML.
2
Аудит ОС. Lynis: запустите sudo lynis audit system на каждом сервере. Зафиксируйте Hardening Index и все WARNING.
3
Сканирование уязвимостей. OpenVAS: создайте цель из результатов Nmap и запустите политику «Full and fast». Nuclei: дополните шаблонными проверками специфичных CVE и мисконфигураций.
4
Веб-уровень. ZAP: baseline-скан для быстрой проверки, full scan для глубокого анализа. Не забудьте про аутентификацию, если приложение закрыто.
5
Контейнеры. Trivy: просканируйте все используемые образы и файловые системы. Настройте --exit-code 1 для CRITICAL в CI.
6
Централизация. Импортируйте все отчёты в DefectDojo. Настройте дедупликацию, владельцев и SLA.
7
Исправление и повтор. Разработчики закрывают находки. Повторный импорт в DefectDojo автоматически закрывает исправленное и реактивирует регрессии.
Ключевая идея: безопасность сервера — это не разовое сканирование, а непрерывный цикл. Автоматизируйте шаги 1–6 в CI/CD, чтобы новые уязвимости обнаруживались до того, как попадут в production.

Исторические кейсы: почему уровень сервера важен

Equifax не обновила Apache Struts, хотя патч был доступен. Уязвимость на уровне сервера приложений (CVE-2017-5638) позволила злоумышленникам получить доступ к данным 147 миллионов человек. Урок: сканирование серверного ПО и управление патчами — не опция, а необходимость.

Уязвимость в библиотеке Log4j, используемой на миллионах серверов, позволяла выполнить произвольный код. Многие организации не знали, что Log4j используется в их серверных компонентах. Урок: инвентаризация зависимостей и сканирование (Trivy, Nuclei) критически важны.

SQL-инъекция в MOVEit Transfer (серверное ПО для передачи файлов) привела к компрометации тысяч организаций. Урок: даже «внутренние» серверные приложения нуждаются в регулярном сканировании и патчинге.
