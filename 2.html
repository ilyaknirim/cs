OWASP ZAP: Модуль 2 — Продвинутый уровень

Первый модуль дал вам фундамент: прокси, перехват, базовые уязвимости. Теперь пора выйти за рамки ручного тестирования. В этом модуле вы освоите фаззинг, скрипты, аутентифицированное сканирование, современные угрозы из OWASP Top 10 2025 и автоматизацию в CI/CD. А главное — закрепите всё на практике в Juice Shop и DVWA.

Что нового: Fuzzer для поиска скрытых параметров, скрипты на Python и JavaScript для кастомных проверок, настройка аутентификации для сканирования «за логином», AJAX Spider для современных SPA, HUD для работы прямо в браузере, а также baseline- и full-сканы в пайплайне.

Фаззинг (Fuzzer): автоматический перебор полезных нагрузок

Fuzzer в ZAP — это инструмент для автоматической отправки множества вариантов одного и того же запроса с разными значениями параметра. Он незаменим, когда нужно проверить, как приложение реагирует на неожиданные, граничные или вредоносные входные данные.

🎯 Как использовать Fuzzer

Найдите запрос в History или в дереве сайтов, нажмите на него правой кнопкой → Attack → Fuzz…. В открывшемся окне выберите параметр (например, search или id), который хотите фаззить.

Затем выберите полезные нагрузки (payloads): встроенные списки (SQLi, XSS, directory traversal) или загрузите свой файл. ZAP отправит сотни запросов и покажет ответы, которые отличаются от «нормального» — это потенциальные точки отказа.

Совет: Fuzzer работает и с WebSocket-сообщениями. Это позволяет тестировать实时-приложения (чаты, биржи, игры), которые не используют классические HTTP-запросы.
Осторожно: фаззинг генерирует много трафика. Не применяйте его к production-системам без письменного разрешения и предупреждения команды эксплуатации.

Скрипты и расширения: ZAP как платформа

ZAP поддерживает несколько языков сценариев: JavaScript (GraalVM), Zest (графический язык), Python (Jython), Groovy, Kotlin, Ruby, BeanShell. Скрипты могут расширять функциональность, добавлять кастомные правила сканирования, автоматически обрабатывать запросы и даже создавать новые элементы интерфейса.

Активные правила (Active Rules)

Выполняются во время Active Scan. Можно написать собственное правило для поиска специфичной для вашего приложения уязвимости.

HTTP Sender

Скрипт, который выполняется для каждого запроса и ответа, проходящего через ZAP (включая прокси, сканер и фаззер). Идеален для добавления заголовков, логирования или модификации трафика на лету.

Fuzzer HTTP Processor

Обрабатывает сообщения фаззера до или после отправки — например, для подписи запросов или расшифровки ответов.

Extender

Добавляет новые функции, включая элементы UI и конечные точки API. Позволяет интегрировать ZAP с внешними системами.

JavaScript (GraalVM)

Включён по умолчанию. Современный движок, хорошая совместимость с экосистемой JS.

Zest

Графический язык сценариев, встроенный в ZAP. Позволяет записывать и воспроизводить последовательности действий без написания кода.

Python (Jython)

Требует установки дополнения. Удобен для тех, кто уже знаком с Python.

⚠️ Безопасность: скрипты выполняются с теми же правами, что и сам ZAP. Не запускайте скрипты из непроверенных источников.

Аутентификация и управление сессиями

Без правильной настройки аутентификации ZAP сканирует только страницу входа. Чтобы найти уязвимости в закрытых разделах, нужно научить ZAP логиниться.

1
Создайте контекст (Context). Контекст определяет границы приложения: какие URL включать, какие исключать (например, страницу выхода).
2
Выберите метод аутентификации. ZAP поддерживает Form-based, JSON-based, HTTP/NTLM, Script-based и Browser-based аутентификацию.
3
Настройте индикаторы входа/выхода. Это регулярные выражения или текст, по которым ZAP понимает, залогинен он или нет.
4
Настройте управление сессией. ZAP должен знать, как поддерживать сессию: через cookie, HTTP-заголовок или скрипт.

Почему это критически важно

Аутентифицированные сканы находят в 3–5 раз больше проблем, чем анонимные. Многие уязвимости (IDOR, broken access control, stored XSS) просто не видны без входа в систему.

AJAX Spider: сканирование современных SPA

Классический Spider следует по ссылкам в HTML. Но современные приложения на React, Angular и Vue генерируют контент динамически через JavaScript. AJAX Spider запускает реальный браузер (Firefox или Chrome) и обходит приложение так, как это делал бы человек.

Когда использовать AJAX Spider

Если после обычного Spider вы видите, что найдено мало страниц, а приложение явно содержит больше разделов — попробуйте AJAX Spider. Он «увидит» ссылки, которые появляются только после выполнения JavaScript.

Важно: AJAX Spider можно комбинировать с аутентификацией — тогда он будет обходить и закрытые разделы.

HUD (Heads Up Display) и WebSocket

HUD — это режим, в котором элементы управления ZAP встраиваются прямо в браузер. Вы можете запускать сканирование, видеть оповещения и перехватывать запросы, не переключаясь между окнами.

WebSocket Fuzzer позволяет тестировать实时-приложения, которые обмениваются данными через WebSocket, а не через обычные HTTP-запросы. Это критически важно для современных чатов, бирж и collaborative-инструментов.

OWASP Top 10: что изменилось в 2025 году

Список OWASP Top 10 периодически обновляется. Версия 2025 года отражает новые реалии: цепочки поставок, конфигурации облаков и обработку исключительных ситуаций.

Ключевые изменения

  • A01 Broken Access Control — расширен, поглотил SSRF.
  • A02 Security Misconfiguration — поднялся с 5-го места на 2-е.
  • A03 Supply Chain Failures — новая категория, заменившая «Vulnerable Components».
  • A10 Exceptional Conditions — новая категория, посвящённая обработке ошибок и исключений.
Совет: при сканировании в ZAP обращайте внимание на то, как оповещения (Alerts) сопоставляются с категориями OWASP Top 10. Это помогает приоритизировать исправления.

Broken Access Control и SSRF: главная угроза 2025

В версии 2025 года Broken Access Control остаётся на первом месте и теперь включает Server-Side Request Forgery (SSRF). Это означает, что пользователь может выполнять действия или получать доступ к данным, которые ему не разрешены.

IDOR (Insecure Direct Object References)

Классический пример: в URL есть /api/user/123/profile. Если, изменив 123 на 124, вы видите профиль другого пользователя — это IDOR. ZAP может помочь найти такие параметры, но окончательная проверка часто требует ручного изменения запроса.

SSRF (Server-Side Request Forgery)

Приложение принимает URL от пользователя и делает запрос от имени сервера. Злоумышленник может заставить сервер обратиться к внутренним ресурсам (например, http://169.254.169.254/ в облаке) и вернуть конфиденциальные данные.

Защита: строгий allowlist доменов и IP-адресов, запрет на перенаправления, изоляция сетевого доступа.

Небезопасная десериализация

Эта уязвимость относится к категории A08: Software and Data Integrity Failures. Когда приложение принимает сериализованные данные от пользователя и десериализует их без проверки, злоумышленник может внедрить вредоносный объект, который выполнит код при десериализации.

Пример: Java-приложение принимает сериализованный объект в cookie. Если использовать инструмент вроде ysoserial, можно создать полезную нагрузку, которая при десериализации выполнит команду на сервере. ZAP может помочь обнаружить такие точки входа, но эксплуатация часто требует ручной работы.

Защита: не десериализовать данные из недоверенных источников; использовать безопасные форматы (JSON с валидацией схемы); применять криптографические подписи для проверки целостности.

Практика на OWASP Juice Shop

Juice Shop — современное уязвимое приложение, которое отлично подходит для отработки навыков. Вот несколько заданий, которые можно решить с помощью ZAP.

🧃 Задание 1: Вход администратора через SQL-инъекцию

Откройте страницу входа. В поле email введите ' OR 1=1--. Если приложение уязвимо, вы войдёте как администратор. Используйте ZAP, чтобы перехватить запрос и убедиться, что ввод попадает в SQL-запрос без параметризации.

Что это учит: как SQL-инъекция обходит аутентификацию.

🧃 Задание 2: DOM-based XSS в поиске

Поле поиска отражает ввод в DOM через innerHTML. Введите <iframe src="javascript:alert('XSS')"> и посмотрите, выполнится ли скрипт. ZAP может помочь перехватить и модифицировать запрос.

🧃 Задание 3: Подделка отзыва (IDOR)

Форма отзыва отправляет поле UserId, которое на клиенте установлено в ваш ID. Перехватите запрос в ZAP и измените UserId на ID другого пользователя. Сервер должен принять отзыв от его имени.

🧃 Задание 4: Поиск скрытой страницы scoreboard

Используйте AJAX Spider или просмотрите JavaScript-бандлы, чтобы найти путь к странице score-board. Это учит важности анализа клиентского кода.

Больше заданий: официальное бесплатное руководство «Pwning OWASP Juice Shop» содержит пошаговые решения и подсказки для всех челленджей.

Практика на DVWA (Damn Vulnerable Web Application)

DVWA — классический PHP/MySQL-полигон, который позволяет отрабатывать атаки на разных уровнях сложности. ZAP можно использовать для перехвата и модификации запросов к DVWA.

💀 Задание 1: Command Injection

На странице Command Injection введите IP-адрес и добавьте ; whoami. Если приложение уязвимо, оно выполнит команду. Перехватите запрос в ZAP, чтобы увидеть, как параметр передаётся в shell.

💀 Задание 2: File Inclusion (LFI)

На странице File Inclusion попробуйте открыть ../../../../etc/passwd. ZAP поможет перехватить запрос и изменить параметр page.

💀 Задание 3: CSRF

На странице CSRF измените пароль через скрытую форму. ZAP может помочь проанализировать, какие параметры передаются и есть ли токены защиты.

Совет: DVWA имеет четыре уровня сложности (Low, Medium, High, Impossible). Начните с Low, чтобы понять механизм, затем переходите к Medium и High, где появляются фильтры и защиты.

Автоматизация и интеграция в CI/CD

ZAP можно запускать в headless-режиме (без графического интерфейса) и встраивать в пайплайны GitHub Actions, GitLab CI или Jenkins. Это позволяет автоматически проверять безопасность при каждом коммите или перед релизом.

Baseline Scan (пассивный)

Быстрый и безопасный скан: только пассивный анализ, без активных атак. Подходит для staging и даже production.

docker run --rm -v $(pwd)/zap-work:/zap/wrk/:rw \
  ghcr.io/zaproxy/zaproxy:stable zap-baseline.py \
  -t https://staging.example.com \
  -r baseline-report.html

Full Scan (активный)

Полный скан с активными проверками. Запускайте только на тестовых средах, где допустимы агрессивные тесты.

zap-full-scan.py -t https://staging.example.com -r full-report.html

API Scan

Сканирование на основе OpenAPI/Swagger-спецификации. Позволяет проверить все эндпоинты API автоматически.

zap-api-scan.py -t https://api.example.com/openapi.json -f openapi

GitHub Actions (пример)

name: OWASP ZAP Baseline Scan
on: [push]
jobs:
  zap_scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run ZAP Baseline Scan
        uses: zaproxy/action-baseline@v0.12.0
        with:
          target: 'https://staging.example.com'
          rules_file_name: '.zap/rules.yaml'
          fail_action: true
Гейтинг: настройте порог срабатывания (например, падать при наличии High-risk находок), чтобы пайплайн останавливался при критических уязвимостях. Это основа DevSecOps.

Исторические кейсы: чему учат крупнейшие атаки

Современные уязвимости редко существуют в вакууме. За каждой категорией OWASP Top 10 стоят реальные инциденты.

Equifax не обновила Apache Struts, хотя патч был доступен. Злоумышленники использовали известную уязвимость (CVE-2017-5638) для кражи данных 147 миллионов человек. Штраф и урегулирования превысили 1,7 миллиарда долларов. Этот кейс стал хрестоматийным примером того, почему управление зависимостями и своевременное обновление критически важны.

Атакующие скомпрометировали процесс сборки обновления SolarWinds Orion и внедрили бэкдор. Обновление было подписано легитимным сертификатом, поэтому тысячи организаций, включая государственные агентства США, установили вредоносный код. Это подчеркнуло важность целостности цепочки поставок и мониторинга аномалий.

Уязвимость в библиотеке Log4j позволяла выполнить произвольный код через specially crafted строку в логах. Миллионы Java-приложений по всему миру оказались под угрозой. Log4Shell показал, как одна уязвимость в широко используемой зависимости может иметь глобальный масштаб.

Кампания против MOVEit Transfer использовала SQL-инъекцию для доступа к файлам тысяч организаций. Этот инцидент напомнил, что классические инъекции остаются актуальными, особенно в managed file transfer-решениях, которые часто считаются «внутренними» и менее защищёнными.
